# 03 · 도플러 속도·방향 추정

> 모듈: [`doppler_speed.py`](../doppler_speed.py) · 검증: [`doppler_cycle_test.py`](../doppler_cycle_test.py)

## 물리 기초

등속으로 다가오는 음원의 수신 파형은 **전체가 시간압축**된다. 따라서 도플러 인자 `k`에 대해:

```
피치:      f_obs = f_src · k
사이클주기: T_obs = T_src / k          (같은 k, 역방향)
여기서  k = c / (c − v_r),   c = 343 m/s,  v_r = 시선속도
```

**실측 검증** (정지 클립을 배속 k로 변형 → 재측정): 사이클 오차 1.8%, 피치 오차 0.9%. 물리 그대로 성립.

통과(pass-by) 시 source-무관 관계:
```
f_접근 / f_이탈  =  T_이탈 / T_접근  =  (c + v) / (c − v)
→  v = c · (r − 1) / (r + 1)
```

## 절대속도는 어디까지 가능한가

### 단일 관측의 정보이론 한계

`f_obs`만으론 `v`를 못 푼다 — `f_src`(이 사이렌의 정지 주파수)를 모르기 때문. 1000 Hz 관측은:

| 정체 | 실제 속도 |
|------|----------|
| 960 Hz 사이렌(접근) | +43 km/h |
| 1000 Hz 사이렌(정지) | 0 km/h |
| 1040 Hz 사이렌(이탈) | −40 km/h |

→ 모집단 기준값의 **산포 자체가 절대속도 오차의 바닥**:

| 차종 | 사이클 기준 | 피치 기준 |
|------|-----------|----------|
| 경찰차 | ±56 km/h | ±202 km/h |
| 구급차 | ±69 km/h | ±268 km/h |
| 소방차 | ±89 km/h | ±149 km/h |

**사이클이 피치보다 ~2–4배 나은 앵커** (CV 4.6–7.2% vs 12–22%). 하지만 모집단 기준만으론 정밀 절대속도는 불가.

### 통과(pass-by) 자기참조 → 정밀

같은 사이렌의 접근/이탈 비율은 `f_src`가 소거되어 **source-무관**. 이걸로 정밀해진다.

## 견고형 추정기: 로그-스펙트럼 상호상관

순진한 "프레임별 최대 peak 추적"은 **배음 사이를 널뛰어**(320↔640↔960) 8% 도플러를 46% 가짜 변동이 덮는다(초기 시도 오차 230 km/h).

**해결**: 접근·이탈 구간의 평균 스펙트럼을 **로그-주파수축에서 상호상관**. 도플러는 모든 배음을 같은 비율로 옮기므로, 전 배음이 상관에 함께 기여 → 배음 널뛰기·잡음에 강건.

추가 안전장치:
- **물리 상한 캡** (ratio < 1.2 ≈ 100 km/h): 배음 오정합으로 인한 과대추정 차단
- **prominence 게이트**: 경쟁 피크가 비슷하면 기권(배음 모호성)
- **사이클 비율 교차검증**: 진폭 envelope 주기로 2차 확인

```python
from doppler_speed import estimate_passby, synth_passby, load_wav
sr, seg = load_wav(path)   # 클립 전체 — area.start/end 전달 금지 (docs/01 함정 #3)
est = estimate_passby(seg, sr)
# → {"v_kmh", "v_spec", "v_cycle", "direction", "strength", ...}
```

## 검증 결과 (합성 pass-by + 잡음)

`synth_passby`(지연시간 기반 물리적 통과 합성)로 알려진 속도를 주입 → 추정 오차:

| 주입 속도 | clean | 20 dB | 10 dB |
|-----------|-------|-------|-------|
| 30 km/h | 중앙값 5.9 | 6.1 | 6.6 |
| 50 km/h | 6.5 | 6.6 | 6.6 |
| 70 km/h | 5.9 | 8.0 | 5.3 |

- **중앙값 오차 5–8 km/h, 10 dB 잡음까지 거의 불변** (로그-스펙트럼이 잡음에 강함). 검출률 24–25/25.
- 평균 오차는 더 큼(~14): 소방차 극단 사이클(0.17 s yelp / 4.7 s wail)이 배음 오정합으로 튐 → 실시간에선 **슬라이딩 윈도우 다중 추정의 중앙값**으로 흡수.
- 조건: 클립 12 s 윈도우 · d=8 m (측면 거리). **유한 윈도우·원거리 차선에서는 기하 바이어스가 추가**된다 — 아래 §기하 한계.
- (수치는 좌표계 결함 수정 후 전체 클립 재검증값 — 이전 7–9/평균 24에서 개선: 클립 앞 2 s를 버리지 않게 되어 유효 구간이 길어짐)

### 방식 B 비교용 정식 베이스라인 (`speed_baseline.py`, 120 정지 클립)

**인위적(제작=정지) 사이렌** 중 f0 글라이드<80 Hz로 검증한 정지 베이스 120개에 `synth_passby(v, d_min)` 주입 → `estimate_passby` 역산. v×SNR×d_min 스윕:

| v (km/h) | clean | 5 dB | | d_min | 평균 오차 | 기권율 |
|---|---|---|---|---|---|---|
| 10 | 6.8 | 6.5 | | **5 m** | **2.6** | 1% |
| 30 | 4.6 | 4.7 | | **15 m** | **4.3** | 1% |
| 50 | 3.7 | 3.5 | | **30 m** | **8.3** | 1% |
| 80 | 3.3 | 3.9 | | | | |

- **노이즈 거의 면역**: clean→5 dB 오차 불변, 기권율 1–2% 유지. → "B의 값어치 = A가 기권하는 저SNR 메우기"는 **약함** (A가 저SNR에서도 안 기권).
- **느린 속도가 더 어려움**(10 km/h 6.8 > 80 km/h 3.3): 빠를수록 도플러 비율↑ → 측정 쉬움.
- **진짜 약점 = 차선 거리**(d_min 30 m → 8.3): 시선속도 과소추정(아래 §기하 한계). 방향 정확도 93.8%.
- ⚠ **home-advantage**: synth_passby가 retarded-time 물리로 생성하고 A가 같은 물리로 역산 → 합성에서 이 숫자는 절반은 자기 신호 읽기. **진짜 시험은 자연 녹음 A–B 일치율** ([docs/04](04-architecture-and-comparison.md) §교차검증).

## 기하 한계: 차선 거리와 시선속도

도플러가 재는 것은 도로 속도가 아니라 **시선(반경) 방향 속도** `v_r = v·cosθ`다.
측면 오프셋 d(차선 거리)를 두고 직선 통과하는 차량의 시선속도는:

```
v_r(x) = v·|x| / √(d² + x²)        (x = 통과점 기준 도로상 위치)
멀리서(|x| ≫ d): v_r → v (도로 속도 전체) · 통과 순간(x=0): v_r → 0
```

- `estimate_passby`는 윈도우 **앞/뒤 30%** — 즉 전이 구간을 건너뛴 **점근 구간의 비율**을 쓰므로,
  1차적으로는 d에 둔감하게 도로 속도 v를 복원한다 (frac=0.3 설계 이유).
- 단 **유한 윈도우**에서는 d가 클수록 앞/뒤 구간이 전이 구간에 걸려 **과소추정** 바이어스:

| 차선 거리 d | 5 s 윈도우 (통과 중앙 정렬, v=60 km/h) 기대 바이어스 |
|---|---|
| ~3.5 m (옆 차선) | −1% 수준 |
| ~10 m (3개 차선 건너) | −6~12% |
| ~30 m (건너편 도로) | −30%± → **tier 경계 오분류 위험** |

- 위 검증(5–8 km/h)은 12 s·d=8 m의 유리한 조건 — 실시간 5 s·원거리 차선에서 나빠진다.
  → [docs/04](04-architecture-and-comparison.md) 평가 프로토콜의 **d_min × 윈도우 스윕**으로 정량화.
- 완화: ① 슬라이딩 다중 윈도우 중앙값(계획됨) ② 통과 전후로 누적 윈도우 확장
  ③ tier 경계 캘리브레이션 ④ (이후) **TDOA 방향각**으로 통과 기하를 먼저 알아내 구간 선택 보정.

**진폭(음압)으로는 왜 안 되나**: 진폭 추세는 "가까워지는 중" 판별(부호)에는 견고하지만,
절대 역산은 불가 — 사이렌마다 출력 음압이 다르고(소스 레벨 미지) 거리도 미지라
`1/r` 하나에 미지수가 둘이다. envelope의 모양(피크 날카로움)이 d/v 정보를 갖긴 하나 잡음에 취약 → 보조 신호로만.

## "n배속 증강으로 DL이 속도 학습" 에 대한 정리

이 아이디어는 **증강 방식에 따라 갈린다.**

| 증강 | 물리적 의미 | 라벨 일관성 | DL 학습 |
|------|-----------|-----------|---------|
| 균일 n배속 | 등속 → source 피치와 혼동 | ❌ 모순 | ❌ ±56 km/h 한계 |
| **synth_passby** | 통과 전이 → source-무관 비율 | ✅ 일관 | ✅ 가능 |

- 균일 배속은 "피치만 옮긴 것"이라 정지 사이렌과 구분 불가 → 같은 소리에 다른 속도 라벨 → DL은 평균 회귀(±56 km/h). `f_src`를 알아도 *산포*가 한계라 못 깬다.
- **`synth_passby`로 증강하면** 통과 비율이 source-무관이라 라벨이 일관 → DL이 진짜 속도(또는 단계)를 학습 가능. **이것이 "DL 속도 역산"의 올바른 형태**이며, 물리 DSP 분기를 학습형으로 대체하는 길.

## 실용 결론

- **방향(접근/이탈)**: 매우 견고 (진폭 추세 + 글라이드 부호). 안전 알림의 핵심.
- **속도 단계(빠름/느림)**: 충분히 가능. 정밀 km/h는 통과 비율로 5–8 km/h (근거리 조건).
- **절대 km/h 캘리브레이션**: 나중 매핑(경계값 보정)으로 처리.
